# Models

`nanlm0.*` is generated by `tools/build_model.sh`:

- `nanlm0.nas` — editable NaN16 assembly emitted by the C adapter. This is the
  source of record for the first model.
- `nanlm0.nan` — assembled `NNNN_PPPPPPPP_FFFF` words, run by `nanlm_vm`.
- `nanlm0.expected` — one two-digit hex class per query.
- `nanlm0.manifest` — dimensions, seed, noise, and data offsets.

`nanlm_ctx.*` is generated by `tools/build_ctx.sh` and is the M2a model:

- `nanlm_ctx.nas` — NaN16 assembly with the context runtime.
- `nanlm_ctx.nan` — assembled words.
- `nanlm_ctx.expected` — `CC HHHHHHHH` per query: class and query-vector hash.
- `nanlm_ctx.manifest` — dimensions and data offsets.

The M2a runtime performs:

```
v_i = C[b_i] XOR P[i]
q   = majority(v_0, v_1, v_2)
```

The expected hash makes a label-only shortcut fail. Zeroed positions, swapped
prototypes, and step starvation are negative gates.

`nanlm_lm.*` is generated by `tools/build_lm.sh` and is the byte-level M2b
base:

- `nanlm_lm.nas` — the 2,048-bit, 256-byte, 4-prototype-per-byte model.
- `nanlm_lm.nan` — assembled words.
- `nanlm_lm.expected` — predicted byte + query hash for 32 held-out contexts.
- `nanlm_lm.manifest` — dimensions, corpus split, and metrics.

M2b is a real byte-level associative language model, but not a competitive one:
**25% top-1 vs 50% for an order-3 n-gram** on the held-out Alice excerpt. HDC
probability calibration is not implemented, so only the n-gram bits/byte is
reported. The runtime matches the C adapter on every predicted byte and hash.

Do not hand-edit the `.nan` files; edit the trainer or the `.nas` source. The
`.nan` and expected files are regenerated by the build scripts.
