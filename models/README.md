# Models

`nanlm0.*` is generated by `tools/build_model.sh`:

- `nanlm0.nas` — editable NaN16 assembly emitted by the C adapter. This is the
  source of record for the first model.
- `nanlm0.nan` — assembled `NNNN_PPPPPPPP_FFFF` words, run by `nan_cli`.
- `nanlm0.expected` — one two-digit hex class per query.
- `nanlm0.manifest` — dimensions, seed, noise, and data offsets.

`nanlm_ctx.*` is generated by `tools/build_ctx.sh` and is the M2a model:

- `nanlm_ctx.nas` — NaN16 assembly with the context runtime.
- `nanlm_ctx.nan` — assembled words.
- `nanlm_ctx.expected` — `CC HHHHHHHH` per query: class and query-vector hash.
- `nanlm_ctx.manifest` — dimensions and data offsets.

The M2a runtime performs:

```
v_i = C[b_i] XOR P[i]
q   = majority(v_0, v_1, v_2)
```

The expected hash makes a label-only shortcut fail. Zeroed positions, swapped
prototypes, and step starvation are negative gates.

It is still not a language model. M2b switches to bytes and a held-out corpus
with an n-gram baseline.

Do not hand-edit `nanlm0.nan`; edit the trainer or the `.nas` source. The
`.nan` and expected files are regenerated by `sh tools/build_model.sh`.
